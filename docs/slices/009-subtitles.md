# Subtitles

## Summary

This slice sends the subtitle tracks of a video to YouTube. The tracks are the
WebVTT files already shown by the blog (`<track>` elements, found by slice 003).
They are sent after an upload, and can also be synchronised afterwards with a
video that is already on YouTube.

## Context

In the existing workflow the subtitles already exist on the blog, are converted by
hand to a format YouTube Studio accepts, and are uploaded in Studio. The plugin
knows each track's file and language, since the page declares them (`srclang`).

YouTube has an API for captions: list the tracks of a video, add one, replace the
file of one. Each call has a quota cost, adding a track being by far the most
expensive (about 400 units, to the best of our knowledge).

## User story

As an administrator, I want the subtitles of my videos to appear on YouTube
without converting and uploading them by hand.

## Goals

- Send every usable subtitle track of a video, one per language.
- Be able to run it again after a track changed, replacing the track instead of
  adding a second one.
- Convert the WebVTT files to a format YouTube is known to accept.
- Never fail an upload because of its subtitles.

## Functional requirements

### 1. Which tracks

The tracks that slice 003 reports as usable: a local file and a language. A track
without a language or without a local file is not sent. When two tracks have the
same language, the first one is used.

### 2. Format

- Setting **Subtitle format**: `srt` (the default) or `vtt`.
- `srt`: the WebVTT file is converted to SubRip, which YouTube accepts without
  doubt. The conversion keeps the texts and the timings and the simple `<i>`, `<b>`
  and `<u>` tags; it drops the header, notes, style and region blocks, cue settings
  (position and alignment), voice and class tags and the in-cue timestamps, decodes
  the usual HTML entities and renumbers the cues.
- `vtt`: the file is sent as it is. It may work as well; it is offered because
  nothing was verified, and because it avoids the conversion.
- The format of the existing workflow ("YouTube's own format") would be SBV. It is
  not offered: SRT is universal and enough.

### 3. Sending

For a video of YouTube and a list of tracks (language, file):

1. list the caption tracks of the video;
2. for each track:
   - when a standard track (not automatic speech recognition) already exists for
     the language, replace its file;
   - otherwise add a new track;
3. report, per language, whether the track was added or replaced, or why it failed.

An error on one language does not stop the others; a quota error stops everything,
since the next calls would fail too.

The track is published (not a draft), has the language of the `<track>` element
and no name, so YouTube shows the language.

### 4. After an upload

- The tracks are stored in the upload job when it is created (language and file),
  so that they do not depend on the page at the end of the upload.
- When the upload completes, the tracks are sent. This is **best effort**: the
  upload stays `done` whatever happens, and a problem is stored in the job as a
  warning, shown by `wp scatter-elsewhere jobs`.

### 5. Afterwards

`wp scatter-elsewhere subtitles <post-id> [<video-id>]` detects the tracks in the
public page of the post and sends them to the YouTube video recorded for that video
(slice 005): the way to retry after a warning, to send the subtitles of a video
that was already on YouTube, or to send a corrected file.

### 6. Code structure

Under `plugin/includes/WP_Scatter_Elsewhere/`:

- `Subtitles/SubtitleConverter.php`: WebVTT to SubRip, pure.
- `YouTube/Multipart.php`: the `multipart/related` body of a caption upload, pure.
- `YouTube/CaptionClient.php`: list, insert and update of caption tracks.
- `YouTube/ApiErrors.php`: readable messages for API errors (shared with the
  video updater).
- `Subtitles/SubtitleService.php`: reads the files, converts them and synchronises
  them with a video.
- `Subtitles/SubtitleResult.php`: the outcome per language.
- `YouTube/Upload/*`: the job carries the tracks and the warning, the service sends
  them after an upload.
- `Settings/UploadSettings.php`, `Admin/SettingsPage.php`, `Cli/Command.php`,
  `YouTube/WordPressFactory.php`: settings and wiring.

## Non-goals

- Track names, drafts, forced or hearing-impaired flags.
- Deleting tracks on YouTube, and removing tracks that disappeared from the page.
- Converting to other formats (SBV and so on) and validating the content of the
  files.
- Subtitle tracks generated by YouTube (automatic captions) are never touched.
- Doing it from an editor interface (later slices).

## Acceptance criteria

1. The conversion produces valid SubRip for a typical WebVTT file: header and notes
   dropped, timings with a comma, cue settings removed, tags cleaned, cues numbered.
2. A track with no existing track for its language is added, with its language and
   the converted file; a language that has a standard track gets that track replaced.
3. An automatic track of the same language does not prevent adding a standard one.
4. An error on one language is reported and the others are still sent; a quota error
   stops the run.
5. A completed upload sends the tracks stored in its job, and stays `done` with a
   warning when they could not be sent.
6. Tracks without a language or file are not stored in the job, and only one track
   per language is.
7. The `subtitles` command sends the tracks detected for a video to the YouTube video
   recorded for it, and refuses when none is recorded.
8. Unit tests cover the converter, the multipart body, the caption client, the
   service and the upload integration without WordPress.

## Notes

- Status: implemented. The converter, the multipart body, the caption client, the
  subtitle service and the upload integration are unit-tested with fake HTTP
  closures (212 tests in total). The upload with a subtitle track was also run
  through the real WordPress wiring with stubbed WordPress functions and fake HTTP.
  The `subtitles` command has only been syntax-checked. Nothing has been run against
  a real WordPress or YouTube yet.

- The accepted formats, the shape of the caption requests and their quota costs
  come from memory of the YouTube documentation and must be confirmed with a real
  upload of subtitles, to be done on the private test video. If SubRip were
  refused, the format setting and the converter are the only things to change.
